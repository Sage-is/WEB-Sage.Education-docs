:::info **Important Note on User Roles and Privacy:**

- **Admin Creation:** The first account created on Sage.is AI-UI gains **Administrator privileges**, controlling user management and system settings.
- **User Registrations:** Subsequent sign-ups start with **Pending** status, requiring Administrator approval for access.
- **Privacy and Data Security:** **All your data**, including login details, is **locally stored** on your device. Sage.is AI-UI ensures **strict confidentiality** and **no external requests** for enhanced privacy and security.
  - **All models are private by default.** Models must be explicitly shared via groups or by being made public. If a model is assigned to a group, only members of that group can see it. If a model is made public, anyone on the instance can see it.

:::

Choose your preferred installation method below:

- **Docker:** **Officially supported and recommended for most users**
- **Python:** Suitable for low-resource environments or those wanting a manual setup
- **Kubernetes:** Ideal for enterprise deployments that require scaling and orchestration

## Docker Deployment Options

### Docker CLI

Follow these steps to install Sage.is AI-UI with Docker.

#### Step 1: Pull the Sage.is AI-UI image

Pull the latest image from the GitHub Container Registry:

```bash
docker pull ghcr.io/Startr/AI-WEB-openwebui:main
```

#### Step 2: Run the container

Run the container with default settings. This command includes a volume mapping to ensure persistent data storage.

```bash
docker run -d -p 3000:8080 -v sage-is-ai-ui:/app/backend/data --name sage-is-ai-ui ghcr.io/Startr/AI-WEB-openwebui:main
```

##### Important flags

- **Volume mapping (`-v sage-is-ai-ui:/app/backend/data`)** keeps your data between restarts.
- **Port mapping (`-p 3000:8080`)** exposes the WebUI on port 3000 of your machine.

##### GPU support

Add `--gpus all` if you have an NVIDIA GPU:

```bash
docker run -d -p 3000:8080 --gpus all -v sage-is-ai-ui:/app/backend/data --name sage-is-ai-ui ghcr.io/Startr/AI-WEB-openwebui:cuda
```

##### Single-user mode (no login)

```bash
docker run -d -p 3000:8080 -e WEBUI_AUTH=False -v sage-is-ai-ui:/app/backend/data --name sage-is-ai-ui ghcr.io/Startr/AI-WEB-openwebui:main
```

:::warning
You cannot switch between single-user and multi-account modes after this change.
:::

##### Connect to a remote Ollama server

```bash
docker run -d -p 3000:8080 -e OLLAMA_BASE_URL=https://example.com -v sage-is-ai-ui:/app/backend/data --name sage-is-ai-ui --restart always ghcr.io/Startr/AI-WEB-openwebui:main
```

Once the container is running, open [http://localhost:3000](http://localhost:3000).

### Updating Docker containers

Keep your deployment current using either Watchtower or a manual update.

#### Option 1: Watchtower

```bash
docker run --rm --volume /var/run/docker.sock:/var/run/docker.sock containrrr/watchtower --run-once sage-is-ai-ui
```

Replace `sage-is-ai-ui` if you named your container differently.

#### Option 2: Manual update

1. Stop and remove the running container:
   ```bash
   docker rm -f sage-is-ai-ui
   ```
2. Pull the latest image:
   ```bash
   docker pull ghcr.io/Startr/AI-WEB-openwebui:main
   ```
3. Run the container again using your preferred command.

### Docker Compose

Docker Compose simplifies multi-container deployments.

If you need Docker itself, start with the [Docker installation tutorial](/docs/tutorials/docker-install).

Docker Compose requires the version 2 CLI (`docker compose`). Older guides using `docker-compose` refer to version 1 syntax.

#### Example `docker-compose.yml`

```yaml
version: '3'
services:
  openwebui:
    image: ghcr.io/Startr/AI-WEB-openwebui:main
    ports:
      - "3000:8080"
    volumes:
      - sage-is-ai-ui:/app/backend/data
volumes:
  sage-is-ai-ui:
```

Start the service:

```bash
docker compose up -d
```

If you need a helper, the repository ships with `run-compose.sh` to assemble the right Compose files.

##### NVIDIA GPU support

Switch the image and add a device reservation:

```yaml
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: all
          capabilities: [gpu]
```

### Podman

Podman is a daemonless alternative to Docker.

Run Sage.is AI-UI:

```bash
podman run -d --name openwebui -p 3000:8080 ghcr.io/Startr/AI-WEB-openwebui:main
```

List running containers:

```bash
podman ps
```

If you run into networking issues, allow host loopback:

```bash
--network=slirp4netns:allow_host_loopback=true
```

See the [Podman documentation](https://podman.io/) for additional configuration.

### Docker Swarm

Deploying with Swarm uses a stack file to run three services (ChromaDB, Ollama, and Sage.is AI-UI).

Create the directories used for persistent volumes before deploying:

```bash
mkdir -p data/sage-is-ai-ui data/chromadb data/ollama
```

#### Sample `docker-stack.yaml`

```yaml
version: '3.9'

services:
  openWebUI:
    image: ghcr.io/Startr/AI-WEB-openwebui:main
    depends_on:
      - chromadb
      - ollama
    volumes:
      - ./data/sage-is-ai-ui:/app/backend/data
    environment:
      DATA_DIR: /app/backend/data
      OLLAMA_BASE_URLS: http://ollama:11434
      CHROMA_HTTP_PORT: 8000
      CHROMA_HTTP_HOST: chromadb
      CHROMA_TENANT: default_tenant
      VECTOR_DB: chroma
      WEBUI_NAME: Awesome ChatBot
      CORS_ALLOW_ORIGIN: "*"
      RAG_EMBEDDING_ENGINE: ollama
      RAG_EMBEDDING_MODEL: nomic-embed-text-v1.5
      RAG_EMBEDDING_MODEL_TRUST_REMOTE_CODE: "True"
    ports:
      - target: 8080
        published: 8080
        mode: overlay
    deploy:
      replicas: 1
      restart_policy:
        condition: any
        delay: 5s
        max_attempts: 3

  chromadb:
    hostname: chromadb
    image: chromadb/chroma:0.5.15
    volumes:
      - ./data/chromadb:/chroma/chroma
    environment:
      - IS_PERSISTENT=TRUE
      - ALLOW_RESET=TRUE
      - PERSIST_DIRECTORY=/chroma/chroma
    ports:
      - target: 8000
        published: 8000
        mode: overlay
    deploy:
      replicas: 1
      restart_policy:
        condition: any
        delay: 5s
        max_attempts: 3
    healthcheck:
      test: ["CMD-SHELL", "curl localhost:8000/api/v1/heartbeat || exit 1"]
      interval: 10s
      retries: 2
      start_period: 5s
      timeout: 10s

  ollama:
    image: ollama/ollama:latest
    hostname: ollama
    ports:
      - target: 11434
        published: 11434
        mode: overlay
    deploy:
      resources:
        reservations:
          generic_resources:
            - discrete_resource_spec:
                kind: "NVIDIA-GPU"
                value: 0
      replicas: 1
      restart_policy:
        condition: any
        delay: 5s
        max_attempts: 3
    volumes:
      - ./data/ollama:/root/.ollama
```

To run without GPUs, remove the `generic_resources` block under the `ollama` service. Make sure CUDA and the NVIDIA Container Toolkit are configured if you plan to use GPUs.

Deploy the stack:

```bash
docker stack deploy -c docker-stack.yaml -d super-awesome-ai
```

## Python Deployment Options

### uv (recommended)

`uv` offers reproducible Python environments with minimal setup.

Install `uv`:

- **macOS/Linux**
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
- **Windows**
  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```

Run Sage.is AI-UI, setting `DATA_DIR` to keep your data:

- **macOS/Linux**
  ```bash
  DATA_DIR=~/.sage-is-ai-ui uvx --python 3.11 sage-is-ai-ui@latest serve
  ```
- **Windows**
  ```powershell
  $env:DATA_DIR="C:\\sage-is-ai-ui\\data"; uvx --python 3.11 sage-is-ai-ui@latest serve
  ```

### Conda

Create an isolated Conda environment:

```bash
conda create -n sage-is-ai-ui python=3.11
conda activate sage-is-ai-ui
pip install sage-is-ai-ui
sage-is-ai-ui serve
```

### Python virtual environments (`venv`)

```bash
python3 -m venv venv
source venv/bin/activate  # Linux/macOS
venv\\Scripts\\activate   # Windows
pip install sage-is-ai-ui
sage-is-ai-ui serve
```

### Updating pip installations

Upgrade to the latest release:

```bash
pip install -U sage-is-ai-ui
```

## Kubernetes Deployment Options

### Helm

Ensure you have a cluster and Helm installed, then run:

```bash
helm repo add sage-is-ai-ui https://sage-is-ai-ui.github.io/helm-charts
helm repo update
helm install openwebui sage-is-ai-ui/sage-is-ai-ui
kubectl get pods
```

Expose the service with port forwarding or your ingress controller to reach Sage.is AI-UI.

### Kustomize

Apply curated manifests with Kustomize:

```bash
git clone https://github.com/Startr/k8s-manifests.git
cd k8s-manifests
kubectl apply -k .
kubectl get pods
```

As with Helm, configure networking (port forwarding, LoadBalancer, or ingress) to access the UI.
